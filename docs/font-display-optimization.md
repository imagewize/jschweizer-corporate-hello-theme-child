# Font Display Optimization - Technical Documentation

**Version**: 2.1.2
**Date**: January 29, 2026
**Author**: Performance Optimization Team

## Overview

This document explains the comprehensive implementation of `font-display: swap` optimization for **ALL fonts** in the Jochen Schweizer Corporate WordPress theme. The optimization addresses PageSpeed Insights warnings about blocking font loading that was causing up to 1560ms delays on mobile devices across Font Awesome and custom MyriadPro fonts.

## Problem Statement

### Initial Issue (Version 2.1.0)

PageSpeed Insights reported:
```
Font display Est savings of 820 ms
Consider setting font-display to swap or optional to ensure text is consistently visible.

URL                                               Est Savings
fa-regular-400.woff2                             820 ms
fa-solid-900.woff2                               820 ms
```

### Updated Issue (Version 2.1.1 - Still Present in 2.1.1)

After fixing Font Awesome, PageSpeed Insights STILL reported font-display issues:
```
Font display Est savings of 1560 ms total
Consider setting font-display to swap or optional to ensure text is consistently visible.

URL                                               Est Savings
fa-solid-900.woff2                               760 ms
fa-regular-400.woff2                             530 ms
MyriadPro-Semibold.ttf                           270 ms
MyriadPro-Regular.ttf                            (additional blocking)
```

**Mobile Score**: 89/100
**Desktop Score**: 95/100

### Root Cause

Multiple fonts were being loaded with `font-display: auto` (or implicit `block` behavior), causing:

1. **Invisible text during font loading** - Users saw blank spaces where icons should appear
2. **Blocking render time** - Browser waited for fonts before showing content
3. **Poor Core Web Vitals** - Negative impact on First Contentful Paint (FCP) and Cumulative Layout Shift (CLS)

### Technical Challenge

**Challenge 1: Font Awesome fonts**
The fonts were declared in **inline `<style>` blocks generated by Elementor**, not through external stylesheets or WordPress enqueue hooks.

**Challenge 2: MyriadPro custom fonts**
The MyriadPro fonts are uploaded to Elementor Pro's Custom Fonts feature. While Elementor Pro provides a filter (`elementor_pro/custom_fonts/font_display`), this filter **only applies when CSS is regenerated**.

**The Core Problem: CSS Caching**
- Elementor caches generated CSS files containing `@font-face` rules
- Changing the filter doesn't apply until cache is cleared
- Even after clearing cache, Elementor may not regenerate CSS immediately
- Multiple `@font-face` declarations throughout the page HTML
- Traditional CSS override approaches don't work reliably with `@font-face` rules

## Solution Architecture

### Approach Comparison

| Approach | Why It Doesn't Work |
|----------|---------------------|
| **CSS Override in Footer** | `@font-face` rules don't follow normal CSS cascade - browsers use the first complete declaration, not the last |
| **WordPress Filters** | Elementor generates inline CSS without using filterable hooks for Font Awesome |
| **Add display=swap to URLs** | Font Awesome fonts are embedded as base64 or self-hosted, not loaded via query parameters |

### Chosen Solution: Multi-Layered Approach

We use a **3-layer defense** to ensure `font-display: swap` is applied to ALL fonts:

#### Layer 1: WordPress Filters (functions.php:52-67)
Apply font-display via Elementor's official filters:
- `elementor/frontend/print_google_fonts/font_display`
- `elementor_pro/custom_fonts/font_display` (for MyriadPro)
- `elementor_icons_font_display`

#### Layer 2: Automatic Cache Clearing (functions.php:127-157)
Force Elementor to regenerate CSS when theme version changes:
- Detects version changes via `jochen_schweizer_theme_version` option
- Clears Elementor Plugin CSS cache
- Clears Elementor Pro Assets Manager cache
- Ensures filters are applied to regenerated CSS

#### Layer 3: JavaScript DOM Manipulation (functions.php:159-242)
Universal fallback that modifies ALL `@font-face` rules **before fonts are fetched**.

**File**: [functions.php:159-242](../functions.php#L159-L242)

```php
function jochen_schweizer_universal_font_display_swap() {
	?>
	<script id="js-universal-font-display-swap">
	(function() {
		function fixFontDisplay() {
			// Process all inline <style> tags
			var styles = document.querySelectorAll('style');

			styles.forEach(function(style) {
				var content = style.textContent;

				// Only process styles containing @font-face rules
				if (/@font-face/i.test(content)) {
					// Replace existing font-display values
					var newContent = content
						.replace(/font-display\s*:\s*auto\s*;/gi, 'font-display: swap;')
						.replace(/font-display\s*:\s*block\s*;/gi, 'font-display: swap;');

					// Add font-display: swap if missing from @font-face rules
					newContent = newContent.replace(
						/@font-face\s*\{([^}]*)\}/gi,
						function(match, content) {
							if (!/font-display\s*:/i.test(content)) {
								return '@font-face {' + content + ' font-display: swap;}'.trim().replace(/;\s*;/g, ';');
							}
							return match;
						}
					);

					if (newContent !== content) {
						style.textContent = newContent;
					}
				}
			});

			// Also try to access linked stylesheets (same-origin only)
			var links = document.querySelectorAll('link[rel="stylesheet"]');
			links.forEach(function(link) {
				try {
					if (link.sheet && link.sheet.cssRules) {
						var rules = Array.from(link.sheet.cssRules);
						rules.forEach(function(rule) {
							if (rule.type === CSSRule.FONT_FACE_RULE) {
								var currentDisplay = rule.style.getPropertyValue('font-display');
								if (!currentDisplay || currentDisplay === 'auto' || currentDisplay === 'block') {
									try {
										rule.style.setProperty('font-display', 'swap', 'important');
									} catch (e) {
										// Stylesheet may be read-only
									}
								}
							}
						});
					}
				} catch (e) {
					// CORS or other access restriction - skip
				}
			});
		}

		// Run immediately
		fixFontDisplay();

		// Run when DOM is ready
		if (document.readyState === 'loading') {
			document.addEventListener('DOMContentLoaded', fixFontDisplay);
		}

		// Run again after short delay to catch dynamic styles
		setTimeout(fixFontDisplay, 100);
	})();
	</script>
	<?php
}
add_action( 'wp_head', 'jochen_schweizer_universal_font_display_swap', 999 );
```

### How It Works

#### Layer 1: WordPress Filters

```php
// For MyriadPro custom fonts (Elementor Pro)
function jochen_schweizer_elementor_custom_fonts_display( $font_display ) {
    return 'swap';
}
add_filter( 'elementor_pro/custom_fonts/font_display', 'jochen_schweizer_elementor_custom_fonts_display' );
```

This filter hooks into Elementor Pro's CSS generation at the source. However, it only applies when CSS is regenerated.

#### Layer 2: Automatic Cache Clearing

```php
function jochen_schweizer_clear_elementor_cache_on_version_change() {
    $stored_version = get_option( 'jochen_schweizer_theme_version' );
    $current_version = HELLO_ELEMENTOR_CHILD_VERSION;

    if ( $stored_version !== $current_version ) {
        // Clear Elementor Plugin CSS cache
        \Elementor\Plugin::instance()->files_manager->clear_cache();

        // Clear Elementor Pro Assets Manager cache
        \ElementorPro\Plugin::instance()->modules_manager->get_modules( 'assets-manager' )->clear_cache();

        update_option( 'jochen_schweizer_theme_version', $current_version );
    }
}
add_action( 'after_setup_theme', 'jochen_schweizer_clear_elementor_cache_on_version_change' );
```

When you bump the version in [functions.php:17](../functions.php#L17), Elementor automatically clears its cache and regenerates CSS with the updated filters.

#### Layer 3: JavaScript Universal Override

1. **Early Injection** (Priority 999 on `wp_head`)
   - Script is injected near the end of `<head>` but before most inline styles
   - Runs before browser begins font fetching

2. **Universal Pattern Matching**
   - Processes **ALL** `<style>` tags containing `@font-face` rules
   - No longer limited to Font Awesome - catches MyriadPro, Google Fonts, and any custom fonts

3. **Dual CSS Manipulation Strategy**
   - **Inline styles**: Modifies `textContent` of `<style>` tags with regex
   - **Linked stylesheets**: Uses CSSOM API to modify `CSSFontFaceRule` objects (same-origin only)

4. **Triple Execution Strategy**
   - **Immediate run**: Processes styles already in the DOM when script executes
   - **DOMContentLoaded run**: Catches styles added dynamically by JavaScript
   - **Delayed run (100ms)**: Catches late-loading dynamic styles

### Technical Decisions

#### Why `wp_head` instead of `wp_footer`?

- Font fetching begins as soon as browser parses `@font-face` rules
- If script runs in footer, fonts may already be loading with wrong `font-display` value
- Early execution in `<head>` ensures modification happens before font requests

#### Why Priority 999?

- Allows most WordPress and Elementor `<head>` content to load first
- Ensures inline styles are present in DOM before our script runs
- High enough to catch Elementor's inline CSS (usually priority 10-100)

#### Why Modify `textContent` Instead of CSSOM?

```javascript
// Why we use this:
style.textContent = newContent;

// Instead of this:
var sheet = style.sheet;
sheet.cssRules[0].style.fontDisplay = 'swap';
```

**Reasons**:
- **Simplicity**: Regex on text is simpler than traversing CSSOM
- **Reliability**: Works with all browsers, no CORS issues
- **Performance**: Single string operation vs multiple CSSOM API calls
- **Completeness**: Catches all `@font-face` declarations at once

## Troubleshooting

### Issue: PageSpeed still shows font-display warning

**Possible causes**:

1. **Cache not cleared**
   - Solution: Clear all caches (WordPress, CDN, browser)

2. **JavaScript not executing**
   - Check browser console for errors
   - Verify script is present in page source
   - Confirm `<script id="js-fontawesome-display-swap">` exists in `<head>`

3. **Font loaded before script runs**
   - Verify script priority is 999 on `wp_head`
   - Check if fonts are preloaded elsewhere with different `font-display`

### Issue: Icons appear with wrong font briefly

**This is expected behavior** (FOUT - Flash of Unstyled Text):

- Icons may briefly show using fallback font (serif/sans-serif)
- This is the trade-off for `font-display: swap`
- Lasts typically 50-200ms on fast connections
- Preferable to 820ms invisible text

**To minimize FOUT**:

1. Ensure font files are properly cached (see cache headers below)
2. Consider preloading Font Awesome fonts:
   ```php
   // Add to functions.php if FOUT is problematic
   function jochen_schweizer_preload_font_awesome() {
       ?>
       <link rel="preload" href="https://www.jochen-schweizer-corporate.de/wp-content/uploads/2024/08/fa-regular-400.woff2" as="font" type="font/woff2" crossorigin>
       <link rel="preload" href="https://www.jochen-schweizer-corporate.de/wp-content/uploads/2024/08/fa-solid-900.woff2" as="font" type="font/woff2" crossorigin>
       <?php
   }
   add_action('wp_head', 'jochen_schweizer_preload_font_awesome', 1);
   ```

### Issue: Script conflicts with other optimizations

**Symptoms**: JavaScript errors, fonts not loading

**Resolution**:
- Check for conflicts with lazy-loading scripts
- Verify no Content Security Policy (CSP) blocks inline scripts
- Test with other optimization plugins disabled

## Additional Recommendations

### 1. Cache Control Headers

Ensure Font Awesome fonts have long cache lifetimes. Add to `.htaccess` or server config:

```apache
# Cache Font Awesome fonts for 1 year
<FilesMatch "\.(woff2?|ttf|eot|svg)$">
    Header set Cache-Control "max-age=31536000, public, immutable"
</FilesMatch>
```

### 2. Font Subsetting

If only using specific Font Awesome icons:
- Generate custom subset with only required glyphs
- Reduces font file size from ~200KB to ~20-50KB
- Use tools like [FontSquirrel Webfont Generator](https://www.fontsquirrel.com/tools/webfont-generator)

### 3. Alternative Icon Solutions

For new projects, consider:
- **SVG icons** (no font loading, better accessibility)
- **Icon components** (tree-shakeable, only load used icons)
- **CSS-only icons** (zero dependencies)
